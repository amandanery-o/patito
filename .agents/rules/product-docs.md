# Product documentation rules

- Give requirements stable IDs in the form `REQ-NNN`.
- Give features IDs in the form `FNNN` and tasks IDs in the form `TASK-NNN`.
- Link every feature to one or more requirements and every task to one feature.
- Write acceptance criteria as observable outcomes, not implementation intentions.
- Separate confirmed decisions, assumptions, open questions, and non-goals.
- Include privacy, offline, migration, analytics, and accessibility implications when relevant.
